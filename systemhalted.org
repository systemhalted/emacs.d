** Custom Settings

Let's protect the startup file from changes made through Emacs' =Customize= interface.
By default, it can write settings into initialization file. However, we want those saved
separately. The =custom.el= will be created only when =Customize= is used.

#+begin_src emacs-lisp :tangle yes
  (setq custom-file
        (expand-file-name "var/custom.el" user-emacs-directory))

  (make-directory (file-name-directory custom-file) t)

  (when (file-exists-p custom-file)
        (load custom-file))
#+end_src

** Files
Do not make backup copies like =notes.org~=

Auto-save files (=#notes.org#=) are still written, because they are what
=M-x recover-this-file= reads after a crash. They just do not belong next to
the file being edited, so every one of them is redirected into a single
directory, with the full path folded into the name to keep them distinct.

The trailing slash on =auto-save-dir= matters. With the uniquify flag set,
Emacs concatenates this string directly onto the mangled file name, so without
the separator the auto-saves land in =var/= as =#!home!...#= instead of inside
=var/auto-save/=. =file-name-as-directory= guarantees the separator.

Lock files are the last stray artifact. Emacs drops a =.#notes.org= symlink
beside a file while it has unsaved changes, so a second Emacs opening the same
file can warn about the clash. Nothing here opens one file from two Emacs
instances at once, and the symlinks confuse tools that walk a directory, so
they are turned off.

#+begin_src emacs-lisp :tangle yes
  (let ((auto-save-dir
         (file-name-as-directory
          (expand-file-name "var/auto-save" user-emacs-directory))))
        (make-directory auto-save-dir t)
        (setq make-backup-files nil
              create-lockfiles nil
              auto-save-file-name-transforms
              (list (list ".*" auto-save-dir t))))
#+end_src

** Key Conventions

If parentheses are not paired, it makes life difficult. So,
=electric-pair-mode= is just for that.

Programs cry when tabs are present for indentation. However, I like pressing tab a lot.
So turning them off so indentation even on tab is space based.

Emacs by default shows the list of buffers that can be killed on =C-x k=.
But my intention is always to kill the current buffer. So, remap it to =kill-current-buffer=.

Also, mapping =s-u= to =revert-buffer= from disk.

Handy conveniences: the column number in the mode line, the clock,
remembering where point was when a file is reopened, and a list of recently
opened files.

#+begin_src emacs-lisp :tangle yes
  (electric-pair-mode 1)
  (setq-default indent-tabs-mode nil)

  (global-set-key (kbd "C-x k") #'kill-current-buffer)
  (global-set-key (kbd "s-u") #'revert-buffer)

  (column-number-mode 1)
  (display-time-mode 1)
  (save-place-mode 1)
  (recentf-mode 1)

  (menu-bar-mode -1)
  (tool-bar-mode -1)
  (scroll-bar-mode -1)

  (auto-fill-mode 1)
  (visual-line-mode 1)
#+end_src

** Minibuffer history

The minibuffer history (previous commands, file names, search terms) is lost
when Emacs exits. [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Savehist.html][savehist]] is built into Emacs (hence =:ensure nil=) and
restores that history on the next start.

#+begin_src emacs-lisp :tangle yes
  ;; enable savehist-mode;
  ;; `:ensure nil` means it would use existing library
  (use-package savehist
    :ensure nil
    :config
    (savehist-mode 1))
#+end_src

** iBuffer
=ibuffer= ships with Emacs, so this is a built-in (=:ensure nil=). It
replaces the basic =list-buffers= menu on =C-x C-b= with a full
major-mode listing where buffers can be marked, filtered (by mode, file
name, size, project), killed or saved in bulk, and grouped. Think of it
as =dired= for buffers.

#+begin_src emacs-lisp :tangle yes
  (use-package ibuffer
    :ensure nil
    :bind ("C-x C-b" . ibuffer))
#+end_src


** Vertico

[[https://github.com/minad/vertico][Vertico]] shows completion candidates as a vertical list instead of the
default single line, so far more candidates are visible at once. It keeps
Emacs' own matching machinery, which the Orderless style (below) drives.

=vertico-directory= adds file-aware helpers to the minibuffer:

- =C-l= (=vertico-directory-up=) moves one directory up.
- =RET= (=vertico-directory-enter=) enters the highlighted directory and keeps
  completing inside it, instead of accepting it as the final value.
- =DEL= (=vertico-delete-char=) at the end of =~/.emacs.d/foo/=
  deletes the trailing path component back to =~/.emacs.d/=.
  Outside that context it is an ordinary backspace.
- =M-DEL= (=vertico-directory-delete-word=) deletes a word inside the path.

  
Example: with =~/Work/e= typed, =C-l= pops you up to =~/Work/=; when a directory
such as =emacs.d= is highlighted, =RET= opens it and completion continues
inside.

The =rfn-eshadow-update-overlay= hook installs vertico-directory-tidy so
shadowed prefixes collapse cleanly:
typing =/etc= after =~/foo/= shows =/etc=, not =~/foo//etc=.
This is part of =Vertico= package.

#+begin_src emacs-lisp :tangle yes
  (use-package vertico
    :ensure t
    :config
    (vertico-mode 1))

  (use-package vertico-directory
    :ensure nil
    :after vertico
    :bind
    (:map vertico-map
          ("C-l" . vertico-directory-up)
          ("RET" . vertico-directory-enter)
          ("DEL"   . vertico-directory-delete-char)
          ("M-DEL" . vertico-directory-delete-word))
    :hook (rfn-eshadow-update-overlay . vertico-directory-tidy))
#+end_src

** Marginalia — annotations in the minibuffer

[[https://github.com/minad/marginalia][Marginalia]] adds a right-aligned annotation column to Vertico's candidates.
The annotation depends on the candidate type: commands show their docstring
summary and key binding, files show mode/size/mtime, buffers show their
major mode and file path, variables show their current value. This turns
=M-x= and =describe-variable= into a passive reference — you can browse
without committing to a selection.

It loads after Vertico because the annotation hook is only useful once a
minibuffer UI is active. The default =marginalia-annotators= registry
already lists the rich annotator first for each candidate category, so
full annotations show on the first prompt — no override required. =M-A=
inside the minibuffer cycles each category to its lighter variants
(=builtin=, =none=) when the default annotation feels too long.

#+begin_src emacs-lisp
(use-package marginalia
  :ensure t
  :after vertico
  :bind (:map minibuffer-local-map
              ("M-A" . marginalia-cycle))
  :init
  (marginalia-mode 1))
#+end_src

** Orderless

[[https://github.com/oantolin/orderless#overview][Orderless]] matches space-separated pieces in any order, treating each piece
as a regexp. Example: =function describe= completes =describe-function=.

Orderless is the first entry in =completion-styles=; when it finds nothing,
Emacs falls back to =basic=, the stock prefix style — a safety net for
completion tables that do not play well with regexps.

File paths are the one deliberate exception: =completion-category-overrides=
switches the =file= category to =basic= plus =partial-completion=, so path
components expand by prefix and wildcards are honored. Example: =~/Wo/e/emac=
expands to =~/Work/environment/emacs=.

#+begin_src emacs-lisp :tangle yes
  (use-package orderless
    :ensure t
    :custom
    (completion-styles '(orderless basic))
     (completion-category-overrides
      '((file (styles basic partial-completion)))))
#+end_src

** Corfu

[[https://github.com/minad/corfu][Corfu]] shows in-buffer completion candidates in a popup at point, so
=completion-at-point= no longer jumps to the =*Completions*= buffer.

Corfu does not create completion candidates itself; it renders whatever the
active completion source already provides. That means Java and Rust receive LSP
completions through Eglot, while other programming modes benefit automatically
when they expose a standard CAPF source of their own.

This setup enables Corfu globally, opens completions automatically after a
short prefix, and cycles back to the start of the candidate list when moving
past the last entry.

#+begin_src emacs-lisp :tangle yes
  (use-package corfu
    :ensure t
    :custom
    (corfu-auto t)
    (corfu-auto-prefix 2)
    (corfu-auto-delay 0.2)
    (corfu-cycle t)
    :config
    (global-corfu-mode 1))
#+end_src

** Config Reload and Visit

I don't want to open init.el and do =C-x C-e= everytime I make changes to this config.
This is a utility function mapped to =C-c r=.

#+begin_src emacs-lisp :tangle yes
  (defun systemhalted/config-reload ()
      "Save and reload the current config"
    (interactive)
    (let* ((config-buffer (get-file-buffer systemhalted/config-file)))
    (when (and config-buffer (buffer-modified-p config-buffer))
      (with-current-buffer config-buffer
      (save-buffer)))
    (message "Reload Emacs Configuration...")
    (org-babel-load-file systemhalted/config-file)
    (message "Reloaded Emacs Configuration")))
   (global-set-key (kbd "C-c r") #'systemhalted/config-reload)

  (defun systemhalted/config-visit ()
    "Open the literate config as a buffer in Emacs for editing"
    (interactive)
    (find-file systemhalted/config-file))
  (global-set-key (kbd "C-c e") #'systemhalted/config-visit)

  (defun systemhalted/visit-generated-config ()
    "Open the generated config file"
    (interactive)
    (find-file (expand-file-name "systemhalted.el" systemhalted/config-directory)))
  (global-set-key (kbd "C-c E") #'systemhalted/visit-generated-config)
#+end_src

** Language Servers

*** Eglot

Eglot is used as the LSP client. It is [[https://www.gnu.org/software/emacs/manual/html_node/eglot/][shipped with Emacs]] (hence
=:ensure nil=) and is far lighter than lsp-mode. When an LSP server is present
it provides completion, go-to-definition, documentation, refactoring and
diagnostics.

#+begin_src emacs-lisp :tangle yes
    (use-package eglot
      :ensure nil
      :hook
        ((java-mode . eglot-ensure)
         (rust-mode . eglot-ensure)))
        ;; equivalent to   (add-hook 'java-mode-hook #'eglot-ensure)
        ;;  (add-hook 'rust-mode-hook #'eglot-ensure)
#+end_src

[[https://joaotavora.github.io/yasnippet/][Yasnippet]] expands short trigger strings into full templates. It is enabled

* Knowledge

** Org

[[https://orgmode.org/][Org]] stores my knowledge base: notes and outlines. Notes live under
=~/Work/organicely/= and are first created in the =00-inbox/= subfolder. To move
a note to its final place, use =M-x dired-jump= then =R (dired-do-rename)=.

The tasks are currently not managed in Emacs.

#+begin_src emacs-lisp :tangle yes

  (defun systemhalted/org-new-inbox-note ()
         "Create a new Org note in the Organicely inbox"
         (interactive)
         (let* ((note-title (read-string "Note Title:"))
                (file-name (concat note-title ".org")))
         (find-file
          (expand-file-name file-name
           (expand-file-name "00-inbox/" org-directory)))
         (insert (concat "#+TITLE:" note-title))))

  (use-package org
     :ensure nil
     :custom
     (org-directory
      (expand-file-name "organicely" "~/Work"))
     :mode
     (("\\.org\\'" . org-mode))
     :bind
     (("C-c c" . systemhalted/org-new-inbox-note)))
#+end_src

** Wordwise

[[https://github.com/systemhalted/wordwise.el][Wordwise]] displays a short dictionary definition above uncommon English words,
like Kindle's Word Wise. It lives in a local checkout rather than a package
archive, so that directory is added to =load-path= and its manual is registered
with Info. =C-c w= toggles the mode.

#+begin_src emacs-lisp :tangle yes
  (defvar wordwise-local-path
        (expand-file-name "~/Work/products/emacs-packages/wordwise.el")
        "Directory holding the local wordwise checkout.")

  (use-package wordwise
    :ensure nil
    :load-path
      wordwise-local-path
    :init
    (with-eval-after-load 'info
      (add-to-list
       'Info-additional-directory-list wordwise-local-path))
    :bind
    ("C-c w" . wordwise-mode))
#+end_src
