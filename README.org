#+TITLE: Palak Mathur's Emacs Configuration
#+AUTHOR: Palak Mathur

* Overview

This is a literate personal Emacs configuration centered on Org notes,
programming with =lsp-mode=, modern minibuffer/completion packages, Git,
documentation, and terminal workflows.  Emacs 30 is recommended; the current
local checks run with Emacs 31.1; CI is configured for Emacs 30.2 and the
Emacs 31 release branch.

=systemhalted.org= is the source of truth.  =init.el= loads the generated
=systemhalted.el= when it is current and otherwise retangles the Org file.
Never edit =systemhalted.el= directly.

* Finding your settings

Open =systemhalted.org= with =C-c e=. It starts folded, with a table linking
common changes to their section; =TAB= opens or closes a section. Package
responsibilities are listed at the top, and explanations stay beside the code.

Startup settings live in Core, completion in Interaction & Completion,
language tools in Development & Languages, notes in Org / Knowledge, and
Dashboard/fonts/themes in Presentation. Terminal and personal packages have
their own sections. =C-c r= reloads after an edit.

* Projects

Projectile uses its saved project list at startup. Run
=M-x systemhalted/discover-projects= after adding repositories under =~/Work=;
change =systemhalted/projects-root= in Projects for a different location.
Discovery is manual so startup does not traverse your workspace tree.

* Requirements

- Emacs 30 or newer is recommended.
- =git= and =rg= should be on =PATH=.
- The first startup needs network access to install external Emacs packages.
- A Nerd Font enables the configured icons and ligatures.
- Language servers, interpreters, and TeX tools are optional; their platform
  installation commands live beside each feature in =systemhalted.org=.

* Installation

Clone this repository somewhere other than =~/.emacs.d=.  From the clone, run:

#+begin_src sh
./link-home.sh
#+end_src

=link-home.sh= creates =~/.emacs.d= only when the path is absent.  If a file,
directory, wrong symlink, or dangling symlink already exists, it refuses to
replace it.  Move the old configuration aside explicitly and rerun the script.
A repository cloned directly as =~/.emacs.d= is detected and left unchanged.

* Running under Omarchy

On [[https://omarchy.org/][Omarchy]] systems the desktop owns the Emacs look, so this config is
driven through =~/.config/emacs/init.el= instead of a home-directory
symlink, leaving Omarchy's theme and font integration (and its file
watchers) in charge:

- =user-emacs-directory= is pointed at this repository before =init.el=
  loads, so runtime commands (=C-c e=, =C-c r=) and state directories
  (=elpa/=, =var/=, =backups/=) resolve here as if the repo were
  =~/.emacs.d=.
- =early-init.el= is symlinked into the home config directory so it runs
  before package activation.
- =systemhalted/omarchy-owned-ui= is set to =t=, so the config defers its
  default and variable-pitch fonts (and any startup theme) to Omarchy;
  =C-c t= and =C-c T= still work as a manual override until the Omarchy
  theme changes again.

The hook-based =./link-home.sh= install is unaffected and remains the
setup on non-Omarchy machines.

* Organicely

Org is a notes-only second brain under =~/organicely/=—not a task manager.
Notes live as individual files in numbered areas, optionally one section deep.
Anything with a done state belongs in Apple Reminders; anything with a date
belongs in Apple Calendar.

The main commands are =C-c c= for capture, =C-c C-w= for moving a note file,
=C-c J= for today's journal, and =C-c n= for note search.  Capture and refile
destinations are constrained to the configured Organicely areas.

* Development and Verification

Retangle after changing Emacs Lisp blocks:

#+begin_src sh
emacs --batch -Q -l org --eval '(org-babel-tangle-file "systemhalted.org")'
#+end_src

Use the isolated runner for configuration checks:

#+begin_src sh
bash test/run-config-tests.sh smoke ert installer tangle compile
bash test/run-config-tests.sh daemon interactive
#+end_src

The runner copies configuration and packages, then sets a temporary home and
runtime directories *before* loading init. A fresh tangle cannot seed your real
Organicely directory, and test sessions cannot rewrite your real package or
session state. Downloaded test packages are cached under =.cache/test-packages/=
for subsequent runs. First use may need network access. Tests use the same
repository entry point on symlink and Omarchy installations.

=daemon= tests commit/rebase finish and abort keys during a delayed terminal
client handoff; =interactive= checks a terminal =--debug-init= startup with
Dashboard, no global snippets, and no unnecessary Org load. Both need
=timeout= and util-linux =script= (macOS can run the batch checks and perform
these checks manually).

For your actual GUI and host integration, run =emacs --debug-init= with your
normal installation. CI is configured to run the isolated checks on Linux
with Emacs 30.2 and =release-snapshot= (the setup action's Emacs 31 branch).
Compiler warnings are reported; compilation errors fail the check. Generated
Lisp is ignored, so the tangle check compares two fresh tangles.
Before committing, run =git diff --check= and =git status --short=.

* Package Policy

Archive packages declare =:ensure t=, built-ins and package-bundled extensions
declare =:ensure nil=, and local checkout branches also declare =:ensure nil=.
A =:vc= declaration is already an explicit package installer and is not paired
with =:ensure=.  Only a missing package artifact (HTTP Not Found or Gone from a configured
archive) refreshes metadata and retries once. Other failures propagate without
retrying.
